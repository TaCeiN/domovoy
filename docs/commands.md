# Команды

Шпаргалка для ручной проверки. Запуск с нуля — [README.md](../README.md).

Приложение работает на настоящих данных — реестрах ГАР ФНС, Фонда
развития территорий, ГИС ЖКХ — и квитанциях жителей. Выдуманные данные
есть в двух помеченных местах: демо-дом для экспертов и заглушка ЖК
в подборе дома.

## Сброс между прогонами

```bash
npm run db:clear
```

Стирает данные приложения: жителей, объекты, лицевые счета, начисления,
счётчики, заявки с историей, объявления, опросы, сессии, кабинеты УК
и председателей.

**Справочники не трогает.** Дома региона, организации и адресный
адресное дерево остаются: это внешние данные из набора региона.

По нелокальной `DATABASE_URL` команда откажется работать — нужен `--force`.
Но боевая база под это правило НЕ попадает: она видна как `127.0.0.1`
или `db`. Подробнее — в разделе «Очистка боевой базы» ниже.

Кабинет УК стирается вместе со всем остальным, поэтому после каждой
очистки его надо завести заново — команда ниже.

| Команда | Что делает со справочниками |
|---|---|
| `npm run db:clear` | оставляет |
| `npm run db:reset` | **сносит схему целиком**, нужен `dataset:load` |

## Кабинет управляющей организации

Кабинет заводится командой, а не регистрацией: в реестре по одной
Ростовской области 713 организаций, а кабинет получает только та, что
реально подключилась.

Найти организацию в реестре — по названию или по ИНН:

```bash
npm run uk:find -- --query Трианон
```

```
6168108630  ООО "УК Трианон"    домов в реестре: 3  (по лицензии 7)
```

Завести кабинет:

```bash
npm run uk:dispatcher -- --inn 6168108630 --login uk-trianon
```

Пароль генерируется на сервере и печатается **один раз** — в базе только
хеш. Своё имя диспетчера задаётся флагом `--name "Диспетчер"`.

Вход — `http://localhost:3000/dispatcher/`.

## Кабинет председателя совета дома

Командой не заводится: председателя назначает УК из своего кабинета,
раздел «Председатели». Пароль там тоже показывается один раз.

Отдельного входа у председателя НЕТ: он заходит в приложение как обычный
житель, а раздел «Совет дома» появляется у него сам. Назначает председателя
управляющая компания из кабинета диспетчера, выбирая жителя дома.

Так и задумано: председатель — третий уровень доступа между жителем и УК,
и выдавать его должен тот, кто отвечает за дом.

## Кабинет оператора

У оператора теперь есть кабинет: `http://localhost:3000/admin/`. Всё, что
делают команды из следующего раздела, есть там же экранами — плюс поиск
жителей, закрытие доступа, заведение кабинетов УК, просмотр любой таблицы
базы на чтение и журнал действий.

Учётка заводится только командой: оператор видит все дома и всех жителей
сразу, и выписать себе такое право никто не должен.

```bash
npm run admin:add -- --login operator --name "Николай"
```

Пароль печатается ОДИН раз — в базе только хеш. Остальное:

```bash
npm run admin:add -- --login operator --reset      # новый пароль
npm run admin:add -- --login operator --disable    # выключить: сессии гаснут сразу
npm run admin:add -- --login operator --enable     # включить обратно
npm run admin:add -- --list                        # кто есть
```

Записи журнала переживают выключение учётки: удаления оператора нет
вовсе, только пометка «выключен».

## Дома без управляющей компании

Дом без УК некому подключить изнутри: председателя назначает УК, а УК
нет. Разрывает этот круг оператор. То же самое есть экранами в кабинете
выше — команды остаются для тех случаев, когда браузер под рукой не нужен.

Очередь заявок «подключите дом» от жителей:

```bash
npm run house:claims
```

Кто уже привязан к дому — пригодится, чтобы выбрать председателя:

```bash
npm run house:residents -- --house "ростовская обл|ростов-на-дону|ленина пр-кт|85/3"
```

Проставить форму управления домом вручную — когда ни ТСЖ, ни ЖСК не
находятся по ИНН, а дом реально живёт непосредственным управлением или
вовсе без него:

```bash
npm run house:form -- --house "ростовская обл|..." --form direct
```

Значения `--form`: `uk`, `tsj`, `zhsk`, `direct`, `none`, `private`,
`unknown`.

Подключить организацию (обычно ТСЖ или ЖСК — у них нет лицензии, и
в наборе региона их может не оказаться) по ИНН вместе со всеми её домами из
справочника ГИС ЖКХ:

```bash
npm run house:org -- --inn 6155090199 --form tsj
```

Это только половина дела: у ТСЖ и ЖСК, как правило, нет своего кабинета
диспетчера, а подтверждает жителей всегда председатель. Команда заявки
дома **не закрывает** и печатает следующий шаг — назначить председателя.

Назначить председателя дому, когда управляющей организации у него нет
(или заявку жителя разумнее закрыть так, а не через `house:org`):

```bash
npm run house:chairman -- --house "ростовская обл|..." --user usr_XXXX
```

Снять председателя, назначенного оператором (дому без УК, включая тот,
что подключён через `house:org` без кабинета диспетчера). Диспетчер из
своего кабинета может снять только председателя дома своей организации —
эта команда для домов, где такой организации либо нет, либо назначение
нужно отменить в обход неё:

```bash
npm run house:chairman:revoke -- --house "ростовская обл|..."
```

`house:form` и `house:chairman` закрывают открытые заявки дома сами:
каждая из них полностью отвечает на просьбу «подключите дом» — форма
управления проставлена или председатель назначен. `house:org` — нет:
организация без кабинета диспетчера сама по себе жителей не подтверждает,
и заявка обязана дождаться `house:chairman`.

## Справочники: набор данных региона

Все дома региона, адресное дерево, управляющие организации с контактами
и координаты приходят одним файлом (`lib/dataset/`).

| Источник | Что даёт |
|---|---|
| ГАР ФНС | адресное дерево и все дома (частные тоже), квартиры, GUID ФИАС |
| Фонд развития территорий (аис.фрт.рф/opendata) | многоквартирные дома, организации: ИНН, телефон, почта, сайт |
| Реестр лицензий ГИС ЖКХ | номер лицензии — отличает УК от ТСЖ |
| OpenStreetMap (Geofabrik) | координаты для карты покрытия |

Загрузить готовый набор из релиза GitHub (секунды на скачивание, минут
пять на запись):

```bash
npm run dataset:load -- --region 61
```

Качает `https://github.com/<DATASET_REPO>/releases/download/dataset-61/dataset-61.ndjson.gz`.
`DATASET_REPO` по умолчанию `TaCeiN/domovoy-datasets` (публичный, только наборы);
закрытому репозиторию нужен
`GITHUB_TOKEN` в окружении. Готовый файл: `-- --file путь.ndjson.gz`.

Загрузчик пишет только реестровый слой домов. Решения оператора
(`house:form`, `house:org`) и правило частного дома переживают любую
перезагрузку набора. Дом, известный по GUID ФИАС, сохраняет ключ. Дом,
выпавший из реестра, не удаляется — теряет реестровую форму и организацию.
Квартиры жителей догоняются сами.

Собрать набор самому — минут пять (при первом запуске ещё качаются ~290 МБ
ГАР и 298 МБ выжимки OSM):

```bash
npm run dataset:build -- --region 61
```

`--no-osm` — без координат. Рабочие файлы — `var/datasets/61/` и
`var/datasets/osm/`, итог — `var/datasets/dataset-61.ndjson.gz`, отчёт
о сшивке печатается в конце. Новый регион — тот же запуск с другим кодом:
GUID субъекта, выгрузки фонда и выжимка OSM находятся сами.

Выложить собранный набор в релиз `dataset-NN` репозитория `TaCeiN/domovoy-datasets`
(нужен `gh` с входом в аккаунт владельца, `gh auth login`; без `gh` команда
печатает шаги для браузера). Файл в релизе заменяется новым по тому же адресу:

```bash
npm run dataset:publish -- --region 61
```

## Карта покрытия домов

Вторая страница генератора квитанций: `http://127.0.0.1:3010/map`.
Цвет дома — уровень покрытия (`lib/coverage/levels.ts`):

- ⚪ только адрес;
- 🟡 известен тип дома или способ управления, контакта нет;
- 🟢 у организации дома есть ИНН и телефон, почта или сайт;
- 🔵 договорились: у дома председатель или у организации кабинет.

Частные и «вероятно частные» дома скрыты по умолчанию и включаются
переключателем, как и «только дома с жителями». Счётчики считаются
по всем домам региона, включая те, что не легли на карту. Координаты —
из набора данных, отдельной выгрузки не нужно.

## Запуск локально

Три команды по порядку:

```bash
docker compose up -d db
```

```bash
npm run db:migrate
```

```bash
npm run dev
```

- `http://localhost:3000/` — приложение жителя
- `http://localhost:3000/dispatcher/` — кабинет УК

Первая поднимает Postgres в контейнере `domovoy-db`, вторая накатывает
схему (нужна только при первом запуске и после изменений в `db/schema.ts`),
третья запускает сервер с автоперезапуском по правкам.

Базы на этой машине — `domovoy` и `domovoy_test`, порт **5433**.
Строки подключения уже прописаны в `.env.local`, руками ничего задавать
не нужно.

Остановить:

```bash
docker compose stop
```

Сам сервер `npm run dev` останавливается по Ctrl+C в его окне.

## Запуск боевого стенда

Все команды боевого стенда идут через `npm run prod:*` и работают
одинаково в PowerShell, cmd и bash. Запускать **из корня проекта**
(там, где лежит `package.json`), а не из вложенной папки.

```bash
npm run prod:up
```

```bash
npm run prod:health
```

`prod:health` стучится сначала мимо TLS, потом по домену — так сразу
видно, что именно легло: приложение или сертификат с пробросом портов.
Ответ `{"status":"ok",...}` с обеих строк означает, что работает всё.

Посмотреть боевую базу глазами:

```bash
npm run prod:studio
```

Открывает Drizzle Studio на `https://local.drizzle.studio`. Отдельная
команда нужна потому, что `npm run db:studio` читает `.env.local` и всегда
показывает базу разработки — перепутать их легко, а выглядит это так,
будто данные пропали.

**Studio пишет в базу сразу, без подтверждения.** За ним живые жильцы.

Если порт занят вторым экземпляром, команда скажет об этом словами
и предложит другой: `npm run prod:studio -- --port 4984`.

Остановить:

```bash
npm run prod:down
```

Полный список — `npm run prod` без аргументов.

**Почему не голый `docker compose`.** Под капотом он и есть, но с двумя
обязательными флагами (`-f docker-compose.prod.yml --env-file .env.prod`):
без них команда уедет в дев-компоуз. Обёртка их подставляет сама.

`down` убирает контейнеры, но **не трогает данные**: они в томах
`domovoy_pgdata` (база) и `domovoy_caddy-data` (сертификат). Следующий `up -d`
поднимет стенд с теми же данными. Стереть их можно только явно —
`docker volume rm` или `down -v`.

### Схема и справочники на боевом

Внутрь контейнера заходить не нужно: база выставлена на петлю
`127.0.0.1:5434`, и команды идут с хоста. Строку подключения собирать
руками не надо — `scripts/prod.mjs` берёт её из `.env.prod` сам.

```bash
npm run prod:migrate
```

```bash
npm run prod:dataset -- --region 61
```

```bash
npm run prod:uk -- --inn 6168108630 --login uk-trianon
```

Двойное тире обязательно: без него npm съест аргументы и не передаст их
скрипту.

**Обычные `npm run db:migrate` и `npm run dataset:load` тут не годятся:**
они подставляют `.env.local` и уехали бы в локальную базу. Разница между
парами команд ровно в этом — куда смотрит `DATABASE_URL`.

Приложение доступно напрямую на `http://127.0.0.1:3001` — это мимо домена
и сертификата, удобно, когда надо понять, в чём дело: в приложении или
в TLS. Наружу оба порта закрыты, снаружи ходит только Caddy.

### Очистка боевой базы

Стереть данные приложения, оставив справочники:

```bash
npm run prod:clear -- --yes
```

Стенд при этом должен быть поднят: без него нет и порта 5434.

Уйдут жители, объекты, лицевые счета, начисления, счётчики, заявки
с историей, объявления, опросы, сессии и кабинеты. Останутся реестр
организаций с домами и справочник адресов — их сносит только `db:reset`,
после которого нужен часовой импорт заново.

Кабинет УК стирается вместе с остальным, поэтому заводится заново:

```bash
npm run prod:uk -- --inn 6168108630 --login uk-trianon
```

**Почему тут требуется `--yes`.** Предохранитель внутри
[../db/clear.ts](../db/clear.ts) требует `--force` только для «чужой»
базы, а локальными считает `localhost`, `127.0.0.1` и `db`. Боевая видна
как `127.0.0.1:5434` с хоста и как `db:5432` изнутри контейнера — то есть
проходит проверку и стёрлась бы молча. Защита писалась против удалённых
баз и от своего же сервера не спасает, поэтому подтверждение добавлено
в обёртку: без `--yes` она печатает, что именно уйдёт, и не делает ничего.

## Остановить, очистить, поднять заново

Полный цикл целиком:

```bash
npm run prod:up
```

```bash
npm run prod:clear -- --yes
```

```bash
npm run prod:uk -- --inn 6168108630 --login uk-trianon
```

```bash
npm run prod:health
```

Очистка требует поднятого стенда — она ходит в базу через петлевой порт.
Поэтому порядок именно такой: сначала `up`, потом чистка. Если стенд был
остановлен, `up` его поднимет; если уже работал — просто пересоберёт
и оставит работать.

Останавливать ради очистки не нужно вовсе. А если всё же нужно погасить:

```bash
npm run prod:down
```

Данные это не тронет: они в томах `domovoy_pgdata` и `domovoy_caddy-data`.

### Если боевой не открывается

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod ps
docker compose -f docker-compose.prod.yml --env-file .env.prod logs app --tail 50
docker compose -f docker-compose.prod.yml --env-file .env.prod logs caddy --tail 50
```

Повторяющееся `challenge failed` с таймаутом в логах Caddy означает, что
до машины не достучаться снаружи: слетел проброс 80 и 443 на её адрес
в локальной сети.

После починки проброса Caddy может ждать до 20 минут — он копит паузу
после неудач. Чтобы не ждать:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod restart caddy
```

## Бот MAX и Домовёнок (ИИ-агент)

Устройство — README, раздел «Домовёнок». Модель — `GIGACHAT_MODEL`
(`GigaChat-2-Pro`). Нужны `BOT_WEBHOOK_SECRET`, `GIGACHAT_AUTH_KEY` в `.env.prod` и
сертификат Минцифры в `certs/russian_trusted_root_ca.crt` (Dockerfile
встраивает его в образ; скачать — gu-st.ru, ссылка в `.env.example`).

```bash
npm run prod:bot -- subscribe     # вебхук на https://$DOMAIN/api/max/webhook
npm run prod:bot -- status        # подписки бота
npm run prod:bot -- unsubscribe   # снять вебхук
npm run prod:bot -- eval          # живые фразы → разбор GigaChat, процент попаданий
npm run prod:bot -- eval-agent    # Домовёнок-агент на живых фразах: ответы и проверка фактов
npm run prod:bot-test             # кто вошёл через MAX
npm run prod:bot-test -- --max-user <id>   # прислать кнопки open_app для проверки
```

Локально (пока вебхук подписан, опрос ничего не получает — сначала
`prod:bot -- unsubscribe`):

```bash
npm run bot:poll    # сообщения боту опросом, ответы от локального сервера
npm run bot:eval          # то же, что prod:bot -- eval, с ключом из .env.local
npm run bot:agent-eval    # то же, что prod:bot -- eval-agent
```

Непонятые сообщения — таблица `bot_miss` (без привязки к жителю,
30 дней): из них пополняются `lib/bot/eval-phrases.ts` и примеры
в `lib/bot/prompt.ts`. Причина `guard: …` — агент назвал число, которого нет
в данных; `agent_give_up` — не уложился в 4 шага.

## Проверка

```bash
npm run check
```

не поднята база.

## Вход без камеры

`getUserMedia` работает только в защищённом контексте, и с телефона по
`http://192.168.x.x:3000` кнопка камеры пропадает — это ограничение
браузера, не приложения.

При `DEV_TOOLS=1` на экране входа есть поле «Вставить строку QR вручную».
Туда кладётся содержимое QR с квитанции:

```
ST00012|Name=ГУП РО "ИВЦ ЖКХ"|PersonalAcc=40602810652090000005|...|persAcc=857000000015641|
```

Второй путь без флага — загрузить фотографию квитанции файлом.

На проде `DEV_TOOLS=0`: ручной ввод выключается переменной, а не выкаткой.


## Демо-дом для экспертов

Обычно всё
делается в кабинете оператора → «Демо-дом»: показать на экране входа,
сбросить (печатает новый пароль кабинета демо-УК), освободить роль.

Запасной путь:

```bash
npm run demo:reset      # завести заново, пароль кабинета demo-uk — в выводе
npm run demo:on         # показать на экране входа
npm run demo:off        # убрать с экрана входа
npm run demo:clear      # стереть целиком
npm run prod:demo       # на бою: то же внутри контейнера (-- clear | on | off)
```
