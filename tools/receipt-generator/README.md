# Генератор фейковых квитанций

Инструмент разработки. Собирает строку платёжного QR по ГОСТ Р 56042-2014
и рисует **сканируемый код** — чтобы проверять приложение на разных домах,
не дожидаясь настоящих квитанций раз в месяц по одному адресу.

```bash
npm run receipts          # против локальной базы
npm run receipts:prod     # против боевого реестра, только чтение
```

Откроется `http://127.0.0.1:3010`.

---

## Зачем он нужен

**Строку некуда вставить.** В бою вход жителя работает только внутри MAX
(`server/config.ts`), а ручной ввод QR выключен. Значит квитанцию надо
именно отсканировать — с экрана телефоном.

**Домов нужно много.** Половина прошлых поломок жила в связке «адрес
из квитанции ↔ адрес из реестра ГИС ЖКХ»: реестр пишет «обл Ростовская,
д. 85/3», квитанция — «г Ростов-на-Дону, д. 85, к. 3». Проверить это
на одном своём доме нельзя.

---

## Что он показывает до сканирования

Главное здесь не QR, а **предсказание**. Выбрав дом, вы видите, что
приложение с ним сделает:

- как разберётся адрес — регион, район, город, микрорайон, улица, дом;
- какой получится ключ дома;
- найдётся ли дом в реестре и какая организация за ним закреплена;
- каким путём он нашёлся — строгим ключом или запасным, без региона.

Раньше это выяснялось только после сканирования и выглядело как
«отсканировал, а дома нет».

Предсказание считают **настоящие модули приложения** —
`lib/address/normalize.ts` и `lib/address/pick-house.ts`, импортом,
а не копией. Копия однажды разъедется, и инструмент начнёт врать.

---

## Что стоит проверять

| Случай | Как воспроизвести |
|---|---|
| Дом из реестра | Найти через поиск, оставить адрес как есть |
| Тот же дом «как в квитанции» | Убрать регион, заменить `85/3` на `85, к. 3` |
| Сельский адрес с районом | Искать «Аксайский», «Верхнетемерницкий» |
| Дома нет в реестре | Вписать выдуманную улицу руками |
| Квитанция расчётного центра | Галочка «Без адреса в квитанции» |
| Сломанный адрес | Номер дома буквами: `д. abc` |
| Заявка не в ту организацию | Получатель «ТНС энерго» — он дом не обслуживает |
| Кодировка win-1251 | ST00011 — так печатают на самом деле |

Про последнее отдельно. **Открытый риск:** нативный сканер MAX отдаёт
готовую строку, а не байты. Если он декодирует win-1251 как UTF-8,
ФИО и адрес приедут мусором (аудит, находка Ф-7). Проверяется так:
сгенерировать в ST00011, отсканировать внутри MAX и посмотреть, что
попало в адрес. Это единственный способ закрыть вопрос.

## Устройство

```
lib/qr-encode.mjs   кодировщик QR, байтовый режим, без зависимостей
lib/cp1251.mjs      кодирование строки в windows-1251
lib/receipt.mjs     сборка строки по ГОСТ (общий для сервера и страницы)
server.mjs          поиск домов, предсказание, раздача статики
public/             страница
```

**Почему свой кодировщик.** В проекте уже лежит декодер
(`public/vendor/jsQR.js`), а кодировщика нет, и нужен он одному
инструменту. Тянуть ради него пакет с транзитивными зависимостями
в проект, где заявки и деньги, — плохой размен.

**Почему это безопасно.** Кодировщик проверяется тем же jsQR:
`qr-encode.test.mjs` кодирует байты, рисует матрицу в пиксели
и декодирует обратно. Ошибка в одной цифре таблицы даёт код, который
выглядит правильным и не сканируется, — глазами такое не проверить.
Одну такую ошибку тест уже поймал: в таблице блоков уровня H
у восьмой версии стояло 5 вместо 6.

**Почему байты, а не строка.** Кодировщик принимает `Uint8Array`
и отказывается принимать строку. Иначе кириллица молча ушла бы в UTF-8,
и получился бы код, который наше же приложение читает мусором.

```bash
npm run test:tools
```

Проверяет и кодировщик (круг через jsQR), и сборку квитанции
(круг через `lib/qr/receipt.ts` — настоящий разборщик приложения).

## Границы

- **Только чтение.** Инструмент ничего не пишет в базу.
- **В образ не едет.** `tools` исключён в `.dockerignore`.
- **Слушает только петлю** — снаружи недоступен.
- Номер лицевого счёта считается от адреса: та же квартира даёт **тот же**
  номер. Иначе каждая генерация заводила бы новый счёт, и проверить
  «повторный скан обновляет, а не плодит» было бы нечем.

## Карта покрытия домов

`/map` — вторая страница инструмента. Отвечает на вопрос «с какими домами
области у нас достаточно данных, чтобы прийти и договориться».

| Цвет | Уровень |
|---|---|
| серый | только адрес из ГАР |
| жёлтый | известен тип дома или способ управления, контакта нет |
| зелёный | у организации дома есть ИНН и телефон, почта или сайт |
| синий | договорились: у дома председатель или у организации кабинет |
| фиолетовый | частный дом по реестру |

Уровни считает `lib/coverage/levels.ts` — то же определение потом покажет
кабинет оператора. Частные и «вероятно частные» дома скрыты по умолчанию.
Счётчики — по всем домам региона, в том числе без места на карте.

Координаты берутся из набора данных региона (`house.lat/lon`, OSM),
отдельной выгрузки инструменту не нужно. Точек сотни тысяч, поэтому они
рисуются тайлами холста, а не маркерами Leaflet.
