# Домовой

Мини-приложение и чат-бот многоквартирного дома в мессенджере MAX.
Трек «Умный город» хакатона MAX.

| | |
|---|---|
| Мини-приложение и бот в MAX | [max.ru/t545_hakaton_max_bot](https://max.ru/t545_hakaton_max_bot) |
| Развёрнутый стенд и API | `https://domovoy.devcore.com.ru` |
| OpenAPI 3.1 | [openapi.yaml](openapi.yaml), на стенде — `/openapi.yaml` |
| Обязательные проверки API | [DATA-API.yaml](DATA-API.yaml), тестовые данные — [API-TEST-DATA.json](API-TEST-DATA.json) |

Тестовые пароли стенда и значения секретов — на служебном слайде презентации,
в репозиторий они не кладутся.

## Быстрый старт — одна команда

Нужен только Docker с Compose v2:

```bash
docker compose up --build
```

Через полторы минуты открыть **http://localhost:3000** → выбрать роль
демо-дома на экране входа. Кабинет УК — http://localhost:3000/dispatcher/,
логин `demo-uk`, пароль `demo-uk-2026`. Набор данных региона догружается
в фоне и запуск не задерживает. Подробности — [«Запуск одной командой»](#запуск-одной-командой),
проверка по шагам — [«Пошаговый сценарий проверки»](#пошаговый-сценарий-проверки).

## Назначение

Житель многоквартирного дома не знает, куда писать о протечке, что стало
с его заявкой и кто за неё отвечает; управляющая компания получает жалобы
звонками и в общих чатах, где они теряются. Домовой связывает их
в одном месте, которое у жителя уже установлено, — в MAX:

- **житель** входит по QR-коду со своей квитанции ЖКУ — адрес, квартира
  и управляющая компания определяются сами, ничего не нужно вводить;
- **подаёт обращение в УК** сразу, без ожидания подтверждений, с фото,
  и видит его путь как переписку: статусы, вопросы диспетчера, ответы;
- **диспетчер УК** работает с очередью обращений в своём кабинете: сроки
  реакции, просрочка, статус, комментарий жителю;
- **председатель совета дома** подтверждает соседей, публикует объявления
  и опросы;
- вокруг этого — начисления по квитанциям, дневник показаний счётчиков,
  аналитика потребления, лента дома, подбор дома на карте;
- **Домовёнок** — ИИ-помощник в приложении и чат-бот в MAX: отвечает на любой
  вопрос живым языком, по данным жителя — только из его же данных в приложении,
  открывает нужный экран и готовит жалобу черновиком, отправляет её житель.

## Основной пользовательский сценарий

**Житель подаёт обращение → УК берёт его в работу → житель видит статус.**

1. Житель открывает мини-приложение из бота в MAX и сканирует QR квитанции.
2. «Подать обращение»: категория, описание, фото — обращение уходит в УК
   его дома.
3. Диспетчер видит его в очереди кабинета `/dispatcher/`, берёт в работу,
   задаёт вопрос или закрывает.
4. Житель получает уведомление в MAX и видит каждый шаг в переписке
   по обращению; выполненное может оценить или вернуть в работу.

## Состав и архитектура

```
 MAX (мини-приложение, бот) ──┐
 браузер                      ├──► app: Node 22 + Fastify ──► db: PostgreSQL 17
 кабинеты /dispatcher/ /admin/┘     раздаёт фронт и API        (данные + справочники)
                                         │
                                         ├─► Bot API MAX (вебхук, уведомления)
                                         └─► GigaChat (Домовёнок: разбор и ответы)
```

- **Фронт** — `public/`: приложение жителя, кабинет диспетчера УК
  (`public/dispatcher/`), кабинет оператора сервиса (`public/admin/`).
  Ванильный JavaScript без сборки, раздаётся тем же сервером, что и API.
- **Бэкенд** — `server/` (маршруты HTTP), `lib/` (логика: доступ, квитанции,
  обращения, счётчики, бот), `db/` (схема Drizzle, миграции, консольные
  команды). Node 22 выполняет TypeScript напрямую, сборки нет.
- **База** — PostgreSQL 17 в своём контейнере.
- **Наборы данных регионов** — дома, адреса и управляющие организации
  региона одним файлом; раздаются релизами репозитория
  [TaCeiN/domovoy-datasets](https://github.com/TaCeiN/domovoy-datasets).
- **Развёрнутый стенд** — те же образ и база за прокси Caddy с TLS
  (`docker-compose.prod.yml`).

```
server/    HTTP-сервер: статика фронта и API
lib/       логика: auth, qr, address, requests, bills, meters, bot, dataset, demo…
db/        схема, миграции (db/migrations), загрузка наборов, консольные команды
public/    фронт жителя; dispatcher/ — кабинет УК; admin/ — кабинет оператора
tools/receipt-generator/  генератор тестовых квитанций с настоящими адресами
docs/      справочники: команды, интеграция с MAX, ГИС ЖКХ, заглушка ЖК
```

## Запуск одной командой

Нужен Docker с Compose v2.

```bash
docker compose up --build
```

Что происходит:

1. `db` — PostgreSQL на порту 5433 хоста;
2. `init` — накатывает миграции и заводит **демо-дом** (разовый шаг, секунды);
3. `app` — приложение на **http://localhost:3000**;
4. `dataset` — **в фоне**, не задерживая запуск, скачивает и загружает набор
   данных Ростовской области (≈130 МБ, около миллиона домов) и заглушку ЖК
   для подбора дома — около 8 минут.

Сборка образа — меньше минуты, от команды до работающего приложения
с демо-домом — около полутора минут (без учёта первой загрузки базовых
образов `node:22-alpine` и `postgres:17-alpine`). Приложение работает
сразу, не дожидаясь набора региона.

Готовность: `curl http://localhost:3000/api/health` → `{"status":"ok"}`.
Открывать именно `localhost`: с другого адреса фронт обращается
к API развёрнутого стенда.

## Домовёнок — ИИ-помощник

Один и тот же помощник в шторке мини-приложения (`POST /api/assistant`) и в чат-боте
MAX (вебхук `/api/max/webhook`). Код — `lib/bot/` (разговор) и `lib/agent/` (агент).

```
сообщение жителя
  ├─ опасность (газ, пожар, «человеку плохо», драка) → номера служб, модель не зовётся
  ├─ «спасибо», чужие квартиры, плановое отключение → ответ кода
  ├─ нет ключа или сверх суточного лимита → шаблоны кода
  └─ GigaChat разбирает сообщение
       ├─ жалоба → черновик обращения (+ уточняющий вопрос), отправляет житель
       └─ всё остальное → агент: модель ⇄ инструменты (до 4 шагов) → проверка фактов → ответ
```

- **Инструменты** (`lib/agent/tools.ts`) — начисления, обращения, счётчики, услуги
  и получатели, контакты дома, отключения, лента и опросы, дела председателя,
  расходы, поиск ЖК, «открыть экран / обращение / ЖК», черновик жалобы. Работают
  с правами приложения: до подтверждения квартиры житель видит только своё, лента —
  после подтверждения, «Совет дома» — председателю. Чьи данные — решает сессия,
  не модель. Номера лицевых счетов в переписку не попадают.
- **Проверка фактов** (`lib/agent/guard.ts`) — каждая сумма, номер обращения,
  телефон, дата и показание в ответе сверяются с данными инструментов. Не
  совпало — вместо ответа модели уходит шаблон кода, промах пишется в `bot_miss`.
- **Кнопки** в ответе даёт только код (инструменты «открыть» и «черновик жалобы»):
  ссылку модель придумать не может. Сам Домовёнок ничего не отправляет и не меняет.
- **Пометка ИИ** — под каждым ответом модели: «Ответ сгенерирован ИИ. Проверяйте
  важное» (поле `ai` в ответе `/api/assistant`, строка в тексте бота MAX).
- **Законы** — общая справка простыми словами и куда обращаться (УК, жилинспекция,
  Роспотребнадзор, прокуратура).
- **Лимиты** — `BOT_DAILY_MESSAGES` сообщений жителя в сутки и
  `GIGACHAT_DAILY_TOKENS` токенов на весь бот; сверх — шаблоны кода.
- **Качество** — `npm run bot:agent-eval`: 25 живых фраз на настоящем GigaChat,
  ответы и итог проверки фактов.

Локально (`docker compose up`) ключа GigaChat нет, и Домовёнок отвечает правилами
и шаблонами кода; полностью — на развёрнутом стенде и в боте MAX.

## Параметры окружения

Для локального запуска ничего задавать не нужно — всё в `docker-compose.yml`.

| Переменная | Где | Назначение |
|---|---|---|
| `DATABASE_URL` | app | подключение к Postgres |
| `COOKIE_SECRET` | app | подпись ссылок и кук; локально — заглушка, на стенде свой |
| `UPLOADS_DIR` | app | каталог вложений к обращениям (том `domovoy-uploads`) |
| `DATASET_REPO` | dataset | откуда качать наборы, по умолчанию `TaCeiN/domovoy-datasets` |
| `DEMO_UK_PASSWORD` | init | пароль кабинета демо-УК, локально `demo-uk-2026` |
| `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, `BOT_WEBHOOK_SECRET` | стенд | бот MAX и его вебхук |
| `GIGACHAT_AUTH_KEY`, `GIGACHAT_MODEL`, `GIGACHAT_*` | стенд | модель Домовёнка (`GigaChat-2-Pro`), лимиты токенов |
| `DOMAIN`, `POSTGRES_PASSWORD` | стенд | домен для TLS и пароль базы |

Полный список с пояснениями — [.env.example](.env.example) (разработка)
и [.env.prod.example](.env.prod.example) (стенд). Настоящих значений
в репозитории нет.

## Работа с данными

- **Реестры** — настоящие открытые данные: ГАР ФНС (дома и адреса),
  реестры Фонда развития территорий (многоквартирные дома, управляющие
  организации), лицензии ГИС ЖКХ, координаты OpenStreetMap. Собираются
  в один файл `dataset-61.ndjson.gz` и грузятся командой
  `node db/dataset-load.ts --region 61` (в Docker её выполняет сервис `dataset`).
- **Квитанции** — платёжный QR по ГОСТ Р 56042-2014: адрес, лицевой счёт,
  сумма и получатель берутся из него. Квитанция — заявка на доступ, а не
  пропуск: подписи в QR нет, поэтому до подтверждения председателем житель
  видит только своё (свои начисления, счётчики и обращения).
- **Чего приложение не знает и не показывает как факт**: статус оплаты
  (в QR его нет — везде «по вашим отметкам»), приём платежей, передача
  показаний в УК (показания — дневник жителя).
- **Вложения** к обращениям хранятся в томе, тип файла проверяется по
  содержимому, публичных ссылок нет — каждый запрос файла проверяет права.

**Смоделированные данные** — только в двух местах, оба помечены в интерфейсе:

- **демо-дом** «ул. Демонстрационная, д. 1» — выдуманный дом, которого нет
  в ГАР, с жителями-персонажами, начислениями, счётчиками, обращениями
  во всех статусах, объявлениями и опросами. Метка «Демо-дом»;
- **заглушка ЖК** в подборе дома — 29 ЖК Ростова с примерными ценами
  и отзывами, фото — рендеры застройщиков. Метка «Примерные данные».

## Тестовые данные

| Набор | Что даёт | Как попадает |
|---|---|---|
| Демо-дом | весь основной сценарий без квитанции и без MAX | автоматически при `docker compose up` |
| Набор региона 61 | настоящие дома, адреса и УК Ростовской области для входа по квитанции и подбора дома | в фоне, сервис `dataset` |
| Заглушка ЖК | карточки ЖК в подборе дома | в фоне, сервис `dataset` |
| [API-TEST-DATA.json](API-TEST-DATA.json) | роли демо-дома и тела запросов для проверки API | файл |
| Генератор квитанций | квитанции с QR на настоящие адреса региона | `tools/receipt-generator/` |

**Чем тестовый набор отличается от полного.** Для основного сценария
достаточно демо-дома: он самодостаточен и заводится за секунды. Полный
набор региона нужен для входа по настоящей квитанции, выбора адреса
из дерева ГАР и подбора дома на карте; локально он догружается в фоне
примерно за 8 минут, на развёрнутом стенде загружен заранее. Наборы других
регионов собираются командой `npm run dataset:build -- --region NN`.

**Роли демо-дома** выбираются прямо на экране входа (в браузере — без
пароля, в MAX — привязкой аккаунта к персонажу):

| Роль | Что показать |
|---|---|
| Председатель совета дома, кв. 1 | раздел «Совет дома»: подтверждение соседей, объявления, опросы |
| Собственник, кв. 12 | начисления за полгода, счётчики с историей, обращения |
| Собственник, кв. 45 | обращение, по которому диспетчер ждёт ответа |
| Собственник, кв. 78 | выполненное обращение — оценить или вернуть в работу |
| Новичок, кв. 30 | неподтверждённый житель: своё и обращение в УК сразу, лента — после подтверждения |

**Кабинет демо-УК**: `http://localhost:3000/dispatcher/`, логин `demo-uk`,
пароль `demo-uk-2026` (только для локального запуска; на стенде свой).

**Кабинет оператора** локально заводится командой, пароль печатается один раз:

```bash
docker compose exec app node db/admin-add.ts --login operator --name "Проверяющий"
```

## Пошаговый сценарий проверки

1. `docker compose up --build`, дождаться `app ... healthy`
   (`docker compose ps`).
2. Открыть http://localhost:3000 — экран входа, блок «Демо-дом» со списком ролей.
3. Выбрать «Собственник, кв. 12». Главная: адрес «Демонстрационная 1, кв. 12»,
   УК «Демо-Дом», сумма к оплате, уведомление об отключении воды, «Мои обращения».
4. «Подать обращение» → категория «Сантехника», описание, при желании фото →
   «Отправить обращение». Обращение появляется в «Моих обращениях» с номером.
5. В другой вкладке открыть http://localhost:3000/dispatcher/, войти
   `demo-uk` / `demo-uk-2026`. Новое обращение — в очереди со сроком реакции.
6. Открыть его, «Взять в работу», указать исполнителя, написать жителю.
7. Вернуться во вкладку жителя → «Обращения» → обращение: в переписке
   статус «в работе» по центру и реплика диспетчера слева.
8. Сменить роль: «Профиль» → «Выйти» → на экране входа «Собственник, кв. 78»
   → выполненное обращение → оценить или
   «Проблема не решена» — обращение возвращается в работу у диспетчера.
9. Роль «Председатель совета дома» → карточка «Совет дома» на главной:
   заявки соседей на подтверждение, объявления, опросы.
10. После фоновой загрузки (около 8 минут; `docker compose logs dataset`
    заканчивается строкой «Заглушка ЖК … 29 ЖК»):
    «Подбор дома» на главной — карта Ростова с районами и ЖК.

Проверка API — по [DATA-API.yaml](DATA-API.yaml) с базовым адресом
`http://localhost:3000` и паролем демо-УК выше.

## Примеры ожидаемого поведения

- `GET /api/health` → `200 {"status":"ok"}`.
- `POST /api/demo/roles/owner12/take` с `{}` → `200 {"token": "…"}`;
  с этим токеном `GET /api/me` отдаёт квартиру 12 демо-дома.
- `POST /api/requests` от жителя → `201` с `id` и номером `number`;
  обращение сразу видно в `GET /api/dispatcher/requests` у демо-УК.
- `POST /api/dispatcher/requests/{id}/status` с `{"status":"in_work"}` → `200`;
  `GET /api/requests/{id}` у жителя отдаёт `status: "in_work"`, в переписке —
  событие о смене статуса.
- Житель без подтверждения председателем (роль «Новичок») подаёт
  обращение сразу (`201`), а лента дома у него пуста (`GET /api/feed` →
  `{"posts":[],"total":0}`), пока председатель не подтвердит.
- Удалить обращение нельзя никому: такого метода нет — только смена статуса.

## Известные ограничения

- Вход по квитанции в браузере на стенде закрыт: в браузере нечем доказать,
  что QR снят с настоящей квитанции. На стенде житель входит из MAX,
  для проверки без MAX — демо-дом.
- Бот и уведомления требуют MAX и публичного HTTPS — локально не работают.
- Статус оплаты, приём платежей и передача показаний в УК не реализованы:
  у сервиса нет доступа к биллингу УК и ГИС ЖКХ. «Оплатить» показывает QR
  квитанции и открывает приложение выбранного банка.
- Набор данных собран для Ростовской области; другой регион — своей командой
  сборки из тех же открытых источников.
- Домовёнок отвечает о законах и правах в ЖКХ только общей справкой: под
  каждым ответом модели — «Ответ сгенерирован ИИ. Проверяйте важное».
  Консультацию юриста он не заменяет.
- Демо-стенд размещён вне РФ; для промышленного запуска с персональными
  данными нужны размещение в РФ и выполнение требований 152-ФЗ.
- Мобильный интернет в режиме белых списков может не открывать
  мини-приложение — проверять по Wi-Fi.

## Остановка и повторный запуск

```bash
docker compose stop            # остановить, данные сохраняются
docker compose up              # запустить снова
docker compose down            # удалить контейнеры, данные в томах сохраняются
docker compose down -v         # удалить всё вместе с базой — следующий запуск с нуля
```

При повторном запуске демо-дом не пересоздаётся — сделанное при проверке
остаётся. Набор региона загружается повторно поверх (безопасно, несколько
минут); чтобы пропустить: `docker compose up --scale dataset=0`.
Сбросить демо-дом к исходному состоянию — кабинет оператора → «Демо-дом»
или `docker compose exec app node db/demo.ts reset`.

## Разработка без Docker-образа приложения

```bash
npm install
docker compose up -d db
cp .env.example .env.local
npm run db:setup
npm run dev
```

`npm run check` — типы, проверка фронта и все тесты (им нужна база
`domovoy_test`, её создаёт `db:setup`). Шпаргалка по командам —
[docs/commands.md](docs/commands.md), интеграция с MAX —
[docs/max-integration.md](docs/max-integration.md).

## Развёрнутый стенд

Тот же образ за Caddy с автоматическим сертификатом Let's Encrypt:

```bash
cp .env.prod.example .env.prod      # заполнить домен и секреты
npm ci
npm run prod:up                     # сборка и запуск
npm run prod:migrate                # схема базы
npm run prod:dataset -- --region 61 # набор региона
npm run prod:mock                   # заглушка ЖК
npm run prod:health
```
